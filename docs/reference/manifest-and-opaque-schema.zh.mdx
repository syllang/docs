# 清单与 Opaque Schema

本文规范 `syl.toml` 工程清单格式以及 `sylc` 用于 `extern cell` DRC 与 CDC 分析的 Opaque Summary（`schema_version = 1`）格式。

---

## `syl.toml` 工程清单

当未显式传入 `--package-root` 时，`sylc` 会从输入路径向上查找最近的 `syl.toml` 作为工程根目录，并据此解析包路径。

### 完整示例

```toml
[project]
name = "my_soc"
version = "0.1.0"
edition = "2026"

[paths]
workspace_roots = ["."]
std_roots = ["vendor/std"]
package_roots = ["src", "lib"]
opaque_summaries = ["summaries/vendor_ip.json", "summaries/cdc_ip.toml"]
```

### `[project]` 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `String` | 可选 | 工程名称；若存在则不能为空白（`E_MANIFEST_INVALID`） |
| `version` | `String` | 可选 | 语义化版本号（如 `"0.1.0"`） |
| `edition` | `String` | 可选 | 语言版本标识 |

### `[paths]` 字段定义

`[paths]` 中的所有路径均相对于 `syl.toml` 所在目录解析：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `workspace_roots` | `Vec<String>` | `["."]` | 工作区根目录列表 |
| `std_roots` | `Vec<String>` | `[]` | 自定义标准库根目录列表 |
| `package_roots` | `Vec<String>` | `[]` | 额外包根目录列表 |
| `opaque_summaries` | `Vec<String>` | `[]` | `.json` 或 `.toml` Opaque Summary 文件路径列表 |

配置的路径条目不能为空白（`E_MANIFEST_INVALID`）。

---

## Opaque Summary Schema（`schema_version = 1`）

Opaque Summary 用于描述 `extern cell` 的内部驱动、消费与时钟域行为，使编译器在没有 SystemVerilog 实现源码的情况下也能执行完整的 DRC 与 CDC 检查。

### 顶层文档字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `schema_version` | `u32` | 是 | 必须为 `1`；其他值将触发 `E_OPAQUE_SUMMARY_INVALID` |
| `summaries` | `Vec<Summary>` | 否 | 不透明项摘要列表（默认 `[]`） |

### `Summary` 条目字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `kind` | `String` | 是 | 不透明项类型（如 `"extern_cell"`） |
| `callable` | `String` | 是 | `extern cell` 名称，不能为空白 |
| `endpoints` | `Vec<Endpoint>` | 否 | 端点描述符列表 |
| `driven_fields` | `Vec<String>` | 否 | 黑盒内部驱动的端口/字段路径 |
| `consumed_fields` | `Vec<String>` | 否 | 黑盒内部读取的端口/字段路径 |
| `domain_behavior` | `DomainBehavior` | 否 | 时钟域行为（如 `same_domain`、`cdc_crossings`） |
| `latency_class` | `LatencyClass` | 否 | 延迟分类（如 `combinational`、`registered`） |
| `protocol_preservation` | `Preservation` | 否 | 协议保持属性 |
| `trust_boundary` | `TrustBoundary` | 否 | 信任边界分类 |
| `backend_constraints` | `Vec<Constraint>` | 否 | 额外后端约束 |

### JSON 示例（`vendor_ip.json`）

```json
{
  "schema_version": 1,
  "summaries": [
    {
      "kind": "extern_cell",
      "callable": "VendorReadyValidSlice",
      "endpoints": [],
      "driven_fields": ["out_data", "out_valid"],
      "consumed_fields": ["in_data", "in_valid"],
      "domain_behavior": "clockless",
      "latency_class": "sequential",
      "protocol_preservation": "preserved",
      "trust_boundary": "trusted_precompiled",
      "backend_constraints": []
    }
  ]
}
```

### TOML 示例（`cdc_ip.toml`）

```toml
schema_version = 1

[[summaries]]
kind = "extern_cell"
callable = "VendorCdcBridge"
driven_fields = ["dst_data", "dst_valid"]
consumed_fields = ["src_data", "src_valid"]
domain_behavior = "clockless"
latency_class = "sequential"
```

## 命令行校验

可使用 `sylc check --manifest` 实测校验工程清单与引用的 Opaque Summary：

```bash
sylc check --manifest path/to/syl.toml path/to/top.syl
```

## 常见 Schema 诊断对照

| 错误码 | 触发条件 |
|--------|----------|
| `E_MANIFEST_PARSE` | `syl.toml` TOML 语法错误或存在未知字段 |
| `E_MANIFEST_INVALID` | `project.name` 为空白或 `[paths]` 中存在空白路径 |
| `E_OPAQUE_SUMMARY_PARSE` | 摘要文件 JSON/TOML 语法错误或存在未知字段 |
| `E_OPAQUE_SUMMARY_INVALID` | `schema_version != 1`、非 `.json`/`.toml` 扩展名或 `callable` 为空白 |
