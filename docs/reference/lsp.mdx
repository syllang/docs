# LSP Reference

Syl implements the Language Server Protocol (LSP) for editor integration. The language server runs as a standalone process communicating with the editor over standard input/output.

---

## Starting the Server

The language server is implemented in the `syl_lsp` crate. Start it with:

```
syl-lsp
```

Once started, the server listens for LSP requests from the editor.

## Supported Capabilities

`syl_lsp` advertises and implements the following `ServerCapabilities`:

- **Incremental document sync (`TextDocumentSyncKind::INCREMENTAL`)**: Efficiently synchronizes incremental edits from the editor.
- **Semantic tokens (`textDocument/semanticTokens/full`)**: Provides compiler-backed syntax and semantic token highlighting.
- **Background DRC channel**: Runs elaboration Design Rule Checks (single-driver, CDC, memory DRC) in a background task without blocking interactive editing.

### Hover

```json
// Editor sends hover request
// Server returns type information
{
    "contents": {
        "kind": "markdown",
        "value": "**Type**: `UInt<8>`"
    }
}
```

Hover displays the type of the expression under the cursor.

### Go to Definition

```json
// Editor sends definition request
// Server returns declaration location
```

Go to Definition jumps from a symbol under the cursor to its declaration, including across files.

### Completion

```json
// Editor sends completion request
// Server returns candidate list
```

Completion suggests available symbols at the cursor, including module ports, signals, local bindings, and keywords.

### Diagnostics

The server publishes diagnostics whenever files change, including error codes, messages, and source spans:

```json
{
    "diagnostics": [{
        "range": {
            "start": {"line": 1, "character": 4},
            "end": {"line": 1, "character": 5}
        },
        "severity": 1,
        "message": "type mismatch: expected `UInt<8>`, found `Bit`"
    }]
}
```

## Editor Integration

### VS Code

To use Syl LSP in VS Code:

1. Build `syl-lsp` and ensure it is in your `PATH`.
2. Install a custom LSP client extension.
3. Configure the LSP command as `syl-lsp`.

### Neovim

Configure with `vim.lsp.start`:

```lua
vim.lsp.start({
    name = "syl",
    cmd = { "syl-lsp" },
})
```

### Helix

Configure in Helix's `languages.toml`:

```toml
[language-server.syl]
command = "syl-lsp"

[[language]]
name = "syl"
language-servers = ["syl"]
```

## Limitations

Current LSP limitations:

- Completion may be slower on very large files
- Rename is not yet supported
- Code actions are not yet supported
- Signature help is not yet supported
