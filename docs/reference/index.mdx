# Reference Manual

Welcome to the Syl Reference Manual. This section is the authoritative, complete specification for the Syl hardware description language, its compiler (`sylc`), standard library (`std.*`), manifest and opaque summary schemas, and tooling.

## Design Philosophy

Syl's type system and constructs are designed around one core goal: **let the compiler catch as many hardware design errors as possible at compile time**.

Compared to Verilog, Syl carries richer type information—the compiler knows every signal's bit width, direction, clock/reset domain, and capabilities (readable, drivable, clock, reset). With this information, the compiler detects connection mismatches, width errors, driver conflicts, and CDC violations before emitting SystemVerilog.

## Type System Overview

Syl types fall into three categories:

- **Basic types:** `Bit` (single bit), `Nat` (compile-time natural number), `Bool` (compile-time boolean).
- **Numeric word types:** `UInt<W>` (`W`-bit unsigned integer, where `W` is a compile-time `Nat`).
- **Composite types:** `[N] T` (arrays), `bundle` (structs), `enum` (enumerations), `interface` (port groups).

## Core Constructs

- **Combinational logic (`map`):** Pure combinational functions with deterministic input-output relationships and no state or side effects.
- **Sequential logic (`reg`, `next`, `mem`):** Registers with explicit clock/reset domains, polarity, and synthesizable memories.
- **Hardware cells (`cell`, `extern cell`):** Parameterizable hardware modules and external/vendor black-box cells.
- **Interfaces and views (`interface`, `view`):** Grouping related ports and defining directional views (`master`/`slave`, etc.).
- **Compile-time constructs (`const`, `fn`, `if`, `for`):** Evaluated at compile time with zero runtime hardware overhead.
