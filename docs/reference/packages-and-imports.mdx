# Packages and Imports

Syl organizes code into packages. Each source file belongs to a package, and packages import declarations from one another using `use`. This page explains package rules, import syntax, `syl.toml` root discovery, and file organization.

---

## Package Concept

Every `.syl` file belongs to a package. The package name is inferred from its file path relative to the package root:

```
project/
├── src/
│   ├── top.syl        # package: project.src.top
│   └── counter.syl    # package: project.src.counter
└── lib/
    └── utils.syl      # package: project.lib.utils
```

Package names are used in `use` statements to reference declarations in other files.

## use Imports

`use` imports declarations from other packages.

### Basic Syntax

```syl
use project.src.counter.Counter
```

This imports the `Counter` declaration from `project.src.counter`, making `Counter` available directly by name.

### Importing Multiple Declarations

```syl
use project.src.counter.Counter
use project.src.counter.Config
```

### Wildcard Import

```syl
use project.src.counter.*
```

This imports all public declarations from `project.src.counter`.

### Importing from the Standard Library

```syl
use std.stream.Stream
use std.stage.Stage
use std.stage.stage_from_stream
```

Standard library packages begin with `std.`.

## Package Organization

### Organizing by Feature

```
project/
├── alu.syl            # ALU types and cells
├── counter.syl        # Counter cells
├── stream.syl         # Stream interface definitions
└── top.syl            # Top-level cell
```

Each file contains declarations for a single functional area, and other files import them with `use`.

### Separating Types and Implementations

Place shared type definitions in one file and the modules that implement them in another:

```syl
# types.syl
enum State { Idle, Running, Done }
bundle Control { state: State, data: UInt<8> }

# fsm.syl
use types.State
use types.Control

cell FSM(ctrl: out Control) { ... }
```

### Avoiding Cyclic Imports

If package A imports package B, package B cannot import package A. The Syl compiler detects and reports cyclic imports.

## Cross-File References

### Example

```syl
# counter.syl
cell Counter<W: Nat>(enable: in Bit, count: out UInt<W>) {
    reg value: UInt<W>
    next value := value + 1
    count := value
}
```

```syl
# top.syl
use counter.Counter

cell Top(enable: in Bit, result: out UInt<8>) {
    let cnt = place Counter<8>(enable: enable, count: result)
}
```

Compile both files together:

```
sylc counter.syl top.syl
```

The compiler resolves `use counter.Counter` and locates `Counter` in `counter.syl`.

### Subdirectory Imports

```syl
# src/sub/counter.syl
cell Counter(enable: in Bit, count: out UInt<8>) { ... }
```

```syl
# src/top.syl
use sub.counter.Counter
```

Import paths are relative to the package root.

## Standard Library Packages

Syl's standard library provides the following packages:

```syl
use std.stream.Stream              // Streaming handshake interface
use std.stage.Stage                // Pipeline stage interface
use std.stage.stage_from_stream    // Adapt Stream to Stage
use std.stage.stage_to_stream      // Adapt Stage to Stream
use std.stage.stage_link           // Connect two pipeline stages
use std.stage.halt_link            // Pipeline link with halt
use std.stage.drop_link            // Pipeline link with drop
use std.pipeline.*                 // Multi-stage pipeline helpers
use std.bundle.*                   // Bundle utilities
use std.logic.*                    // Combinational logic helpers
use std.assert.*                   // Assertion helpers
```

The standard library source lives under `examples/std/` and serves as a reference for idiomatic Syl code.

## Standard Library Package Walkthrough

```syl
use std.stream.Stream
```

`std.stream.Stream` defines a valid-ready handshake interface—the most common interface type in Syl:

```syl
interface Stream<T> {
    payload: T
    valid: Bit
    ready: Bit

    view source {
        out payload
        out valid
        in ready
    }

    view sink {
        in payload
        in valid
        out ready
    }
}
```

Usage example:

```syl
use std.stream.Stream

cell PipelineStage<T, D: Domain>(
    clk: in Clock<D>,
    rst: in Reset<D>,
    upstream: in Stream<T>.sink,
    downstream: out Stream<T>.source,
)
```

## Package Design Guidelines

### Keep File Sizes Moderate

A file size of 100 to 500 lines of Syl code works well. Overly large files are hard to navigate, while tiny files increase import overhead.

### Place Public Interfaces at the Top

Put public types (`bundle`, `interface`, `enum`) at the top of the file and cell implementations below so readers can quickly see what the file exports.

### Compile in Dependency Order

Syl does not require a specific file order on the command line, though listing dependencies first can be convenient.

## Compilation Order

During parsing, the compiler collects top-level declarations from all input files, then runs name resolution to bind `use` imports to their target declarations.

If the compiler cannot locate the file for a `use` path, it reports an error. Common causes include omitting the file from the command line, a misspelled path, or a mismatched filename.

## Common Errors

### Wrong Import Path

```syl
# use counter.Counter    // Wrong if the file is under src/
```

Import paths must use the full package path relative to the package root.

### Name Collisions

```syl
# file1.syl
cell Counter { ... }

# file2.syl
use file1.Counter
# cell Counter { ... }    // Error: Counter name collision
```

Imported declarations cannot share a name with local declarations in the same file. Rename the local declaration to resolve the conflict.

### Cyclic Imports

```
Package A imports Package B
Package B imports Package A
# Error: cyclic import
```

The compiler detects cyclic imports and reports an error. Extract shared types into a third package to break the cycle.

### Using Without Importing

```syl
// Error: Stream used without importing
cell Top(stream: in Stream<UInt<8>>.sink) { ... }
```

Cross-file references require `use`. References within the same file do not require importing.

### `syl.toml` Root Discovery, Unused `use` Checks, and `E_DUPLICATE_MODULE_FILE`

- **`syl.toml` root discovery:** When `--package-root` is not explicitly passed, `sylc` searches upward from the input path for the nearest `syl.toml` to determine the project root and resolve package paths.
- **Unused `use` validation:** The compiler checks whether imported declarations are actually referenced in the current file and emits diagnostics for unused `use` statements.
- **Duplicate module files (`E_DUPLICATE_MODULE_FILE`):** When multiple source files map to the same module path or a module file is loaded twice, the compiler reports `E_DUPLICATE_MODULE_FILE`.
