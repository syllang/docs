# Lesson 5: CDC & FIFO

In real SoCs and FPGAs, subsystems rarely share a single clock. Crossing from one clock domain (`A`) to another (`B`) without proper synchronization causes **metastability**—a physical failure mode that functional RTL simulation often misses completely. In this final lesson, you will intentionally trigger Syl's compile-time CDC checker (`E_MIDDLE_CDC_VIOLATION`), fix the crossing with `std.cdc.Sync2FF` (`@cdc_sync`), buffer data in `std.fifo.SyncFifo`, and verify synthesis with **Yosys**.

## Learning Objectives

By the end of this lesson, you will be able to:

- Trigger and diagnose `E_MIDDLE_CDC_VIOLATION` when a register in domain `A` feeds a register in domain `B` directly.
- Understand how `@cdc_sync(async_in, sync_out, dst_clk)` marks a verified synchronizer boundary.
- Instantiate `std.cdc.Sync2FF` and `std.fifo.SyncFifo` to build a dual-clock bridge (`CdcFifoBridge`).
- Run Yosys synthesis (`read_verilog -sv ...; synth -top CdcFifoBridge`) to confirm the emitted SystemVerilog is synthesis-ready.

## Prerequisites

- Completed [Lesson 4](/docs/tutorials/interfaces-and-pipelines).
- `yosys` installed and available on your `PATH` (`yosys -V`).

## Step 1: Triggering `E_MIDDLE_CDC_VIOLATION`

Create `bad_cdc.syl` with two independent clock domains `A` and `B`, and connect a flip-flop in `A` directly to a flip-flop in `B`:

```syl
cell BadCdc<A: Domain, B: Domain>(
    clk_a: in Clock<A>,
    rst_a: in Reset<A>,
    clk_b: in Clock<B>,
    rst_b: in Reset<B>,
    din: in Bit,
) -> dout: Bit {
    reg stage_a: Bit reset(rst_a, 0)
    next stage_a := din

    reg stage_b: Bit reset(rst_b, 0)
    next stage_b := stage_a

    dout := stage_b
}
```

Run `sylc check bad_cdc.syl`:

```text
error[E_MIDDLE_CDC_VIOLATION]: CDC violation: stage_a launched in clk_a sampled by stage_b in clk_b
   --> bad_cdc.syl:11:5
    |
 11 |     reg stage_b: Bit reset(rst_b, 0)
    |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    |
note: stage_a launched by clk_a
  --> bad_cdc.syl:8:5
   |
 8 |     reg stage_a: Bit reset(rst_a, 0)
   |     ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
   |
error: aborting due to 1 previous errors
```

In Verilog, this bug compiles without a single warning. In Syl, because `stage_a` is bound to `rst_a` (domain `A`) and `stage_b` is bound to `rst_b` (domain `B`), `sylc` proves at compile time that an unsynchronized crossing occurred and rejects it.

## Step 2: How `@cdc_sync` Works in `std.cdc`

In `std.cdc`, `Sync2FF` is annotated with `@cdc_sync(async_in, sync_out, dst_clk)`:

```syl
@cdc_sync(async_in, sync_out, dst_clk)
cell Sync2FF<D_DST: Domain>(
    dst_clk: in Clock<D_DST>, dst_rst: in Reset<D_DST>, async_in: in Bit,
) -> sync_out: Bit {
    reg stage1: Bit reset(dst_rst, 0)
    reg stage2: Bit reset(dst_rst, 0)
    next stage1 := async_in
    next stage2 := stage1
    sync_out := stage2
}
```

The `@cdc_sync` attribute tells `sylc`'s CDC pass: *"This cell intentionally accepts an asynchronous input `async_in` and safely synchronizes it into `dst_clk`'s domain on `sync_out`."*

## Step 3: Building `CdcFifoBridge`

Now create `cdc_fifo.syl`, combining `std.cdc.Sync2FF` for control-signal synchronization with `std.fifo.SyncFifo` for 8-entry, 8-bit data buffering in domain `B`:

```syl
use std.cdc.Sync2FF
use std.fifo.SyncFifo

cell CdcFifoBridge<A: Domain, B: Domain>(
    clk_a: in Clock<A>,
    rst_a: in Reset<A>,
    clk_b: in Clock<B>,
    rst_b: in Reset<B>,
    req_a: in Bit,
    push: in Bit,
    pop: in Bit,
    wdata: in UInt<8>,
    rdata: out UInt<8>,
    full: out Bit,
    empty: out Bit,
    count: out UInt<4>,
    req_b: out Bit,
) {
    reg src_flag: Bit reset(rst_a, 0)
    next src_flag := req_a

    signal synced_req: Bit := place Sync2FF<B>(
        dst_clk: clk_b,
        dst_rst: rst_b,
        async_in: src_flag,
    )
    req_b := synced_req

    place SyncFifo<8, 8, 3, 4, B>(
        clk: clk_b,
        rst: rst_b,
        push: push,
        pop: pop,
        wdata: wdata,
        rdata: rdata,
        full: full,
        empty: empty,
        count: count,
    )
}
```

Run `sylc check` and emit SystemVerilog:

```bash
sylc check cdc_fifo.syl
sylc emit cdc_fifo.syl > CdcFifoBridge.sv
```

Both commands succeed with exit code `0`.

---

## Step 4: Synthesis Verification with Yosys

Finally, verify that `CdcFifoBridge.sv` synthesizes cleanly to standard logic cells and flip-flops using Yosys:

```bash
yosys -q -p "read_verilog -sv CdcFifoBridge.sv; synth -top CdcFifoBridge"
```

Exit code `0` confirms that the generated SystemVerilog is 100% synthesizable—with `Sync2FF` lowered to a two-stage flip-flop chain and `SyncFifo` lowered to memory + pointer registers.

## Common Pitfalls

- **Passing `rst_a` to `Sync2FF<B>`**: `Sync2FF<B>` requires `dst_rst: in Reset<B>`. Passing `rst_a` triggers `E_MIDDLE_RESET_DOMAIN_MISMATCH` because the reset domain does not match `B`.
- **Using `Sync2FF` for multi-bit buses**: `Sync2FF` is for single-bit level signals only. For multi-bit data, use handshakes (`std.cdc.PulseSync`) or a FIFO.
