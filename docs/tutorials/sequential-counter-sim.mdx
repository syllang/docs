# Lesson 2: Sequential Counter & Simulation

In [Lesson 1](/docs/tutorials/first-cell), you built a purely combinational circuit. Real digital systems, however, need state—flip-flops that capture values on clock edges and initialize cleanly on reset. In this lesson, you will build a domain-parameterized 8-bit counter (`Counter8`), inspect its `always_ff` SystemVerilog output, and verify it cycle-by-cycle using **Verilator** and **C++17**.

## Learning Objectives

By the end of this lesson, you will be able to:

- Parameterize a `cell` over a clock domain `D: Domain` using `Clock<D>` and `Reset<D>`.
- Declare flip-flop state with `reg ... reset(rst, 0)` and drive its next-state input with `next`.
- Understand how Syl lowers `reg` to synchronous `always_ff @(posedge clk)` logic in SystemVerilog.
- Write and run a C++17 Verilator testbench to verify sequential behavior.

## Prerequisites

- Completed [Lesson 1](/docs/tutorials/first-cell).
- `verilator` and `g++` (with C++17 support) installed and available on your `PATH`.

## Step 1: Domain-Parameterized Clock and Reset

In Verilog, a clock is just a 1-bit `logic` wire—nothing stops you from accidentally connecting a register clocked by `clk_a` to a reset synchronized to `clk_b`. Syl prevents this at the type level by binding every clock and reset to a **domain** type parameter `D: Domain`:

- `clk: in Clock<D>`
- `rst: in Reset<D>`

Because both `clk` and `rst` share the same `D`, the compiler guarantees they belong to the same clock domain. (We will see how Syl catches cross-domain mistakes in [Lesson 5](/docs/tutorials/cdc-and-fifo).)

## Step 2: Writing `Counter8`

Create `counter8.syl`:

```syl
cell Counter8<D: Domain>(
    clk: in Clock<D>,
    rst: in Reset<D>,
    enable: in Bit,
    clear: in Bit,
) -> value: UInt<8> {
    reg count: UInt<8> reset(rst, 0)

    signal count_next: UInt<8> :=
        select priority {
            clear => 0,
            enable => count + 1,
            default => count,
        }

    next count := count_next
    value := count
}
```

### Hardware Semantics

1. **`reg count: UInt<8> reset(rst, 0)`**: Declares an 8-bit flip-flop `count` initialized to `0` when `rst` is asserted. Because `count` is a `reg`, it is automatically associated with the domain `D` of `rst` (and `clk`).
2. **`signal count_next: UInt<8>`**: Computes the combinational next-state value. Notice the priority order: `clear` overrides `enable`, and `default => count` holds the current value when neither is asserted.
3. **`next count := count_next`**: Connects `count_next` to the `D` (data) input of the `count` flip-flop. Syl enforces that every `reg` has a `next` driver.
4. **`value := count`**: Continuously drives the output port `value` with the `Q` output of the flip-flop.

Check and emit SystemVerilog:

```bash
sylc check counter8.syl
sylc emit counter8.syl > Counter8.sv
```

## Step 3: Inspecting the Generated `always_ff`

Open `Counter8.sv`. You will see:

```verilog
// Generated by sylc. MVP SystemVerilog subset.

module Counter8 (
    input clk,
    input rst,
    input enable,
    input clear,
    output [7:0] value
);
  reg [7:0] count;
  wire [7:0] count_next;
  assign count_next = /* priority */ (clear ? 0 : (enable ? (count + 1) : count));
  always_ff @(posedge clk) begin
    if (rst) begin
      count <= 0;
    end else begin
      count <= count_next;
    end
  end
  assign value = count;
endmodule
```

Notice that `reg count: UInt<8> reset(rst, 0)` lowers to a clean, synchronous active-high reset `always_ff @(posedge clk)` block with non-blocking `<=` assignments.

## Step 4: Writing a C++17 Verilator Testbench

Create `tb_counter8.cpp` to drive `Counter8.sv` through reset, counting, hold, and synchronous clear:

```cpp
#include "VCounter8.h"
#include "verilated.h"
#include <cassert>
#include <iostream>

int main(int argc, char** argv) {
    Verilated::commandArgs(argc, argv);
    VCounter8* dut = new VCounter8;

    auto tick = [&]() {
        dut->clk = 0;
        dut->eval();
        dut->clk = 1;
        dut->eval();
    };

    // Assert synchronous active-high reset
    dut->rst = 1;
    dut->enable = 0;
    dut->clear = 0;
    tick();
    assert(dut->value == 0);

    // Release reset and count 3 cycles
    dut->rst = 0;
    dut->enable = 1;
    for (int i = 1; i <= 3; ++i) {
        tick();
        assert(dut->value == i);
    }

    // Hold when enable = 0
    dut->enable = 0;
    tick();
    assert(dut->value == 3);

    // Clear back to 0
    dut->clear = 1;
    tick();
    assert(dut->value == 0);

    std::cout << "Counter8 Verilator testbench PASSED!" << std::endl;
    delete dut;
    return 0;
}
```

## Step 5: Compile and Run the Simulation

Invoke Verilator to translate `Counter8.sv` to C++, compile it with `tb_counter8.cpp`, and run the resulting binary:

```bash
verilator --cc --exe --build -j 0 -CFLAGS "-std=c++17" \
  --top-module Counter8 Counter8.sv tb_counter8.cpp --Mdir obj_dir
./obj_dir/VCounter8
```

Expected output:

```text
Counter8 Verilator testbench PASSED!
```

## Common Pitfalls

- **Forgetting `next count := ...`**: A `reg` without a `next` driver leaves the flip-flop's `D` input unconnected; `sylc check` will report a missing driver error.
- **Confusing `:=` on `signal` vs `next` on `reg`**: Combinational `signal`s use `name := expr`, whereas sequential `reg`s use `next name := expr` to make register boundaries explicit.
- **Evaluating only `clk = 1` in Verilator**: Always toggle `clk = 0; dut->eval(); clk = 1; dut->eval();` so Verilator detects the rising edge (`posedge clk`).
