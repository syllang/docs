# 第 1 课：你的第一个 Cell

在本课中，你将编写第一个 Syl 硬件模块——在 Syl 中称为 **`cell`**，使用 `sylc check` 进行静态检查，主动触发编译期硬件错误以体会编译器的保护机制，并用 `sylc emit` 生成和解读 SystemVerilog 代码。

## 学习目标

完成本课后，你将能够：

- 验证 `sylc` 工具链并熟练使用 `sylc check` 与 `sylc emit`。
- 声明带有强类型输入端口（`in`）和命名输出端口（`->`）的组合逻辑 `cell`。
- 使用 `bundle` 将多个相关输出信号打包为复合类型。
- 理解为什么 Syl 将硬件连续驱动（`:=`）与软件赋值区分开，以及静态单驱动检查如何消除多驱动冲突。
- 阅读 `sylc` 生成的 MVP SystemVerilog 子集代码。

## 前置条件

- 已安装 `sylc` 并加入环境变量（运行 `sylc --version` 输出 `sylc 0.1.0`）。
- 准备一个练习目录（例如 `mkdir -p ~/syl-tut1 && cd ~/syl-tut1`）。

```bash
sylc --version

```

## 第 2 步：编写最小组合逻辑 Cell

创建 `alu_add.syl`，编写一个计算两个 8 位无符号整数之和的组合逻辑 `cell`：

```syl
cell Add8(
    a: in UInt<8>,
    b: in UInt<8>,
) -> sum: UInt<8> {
    sum := a + b
}
```

逐行解析：

- **`cell Add8(...)`**：声明一个名为 `Add8` 的硬件模块。与"调用一次、顺序执行并返回"的软件函数不同，`cell` 描述的是在硬件中持续存在的物理电路块。
- **`a: in UInt<8>`**：声明一个 8 位无符号输入端口 `a`。注意端口名在冒号之前，后面依次是方向（`in`）与精确位宽类型（`UInt<8>`）。
- **`-> sum: UInt<8>`**：声明输出端口 `sum`，类型为 `UInt<8>`。
- **`sum := a + b`**：用 `a + b` 持续驱动输出线网 `sum`。Syl 使用 `:=` 而非 `=`，强调这是**硬件信号驱动**——一种永久的物理连接，而不是软件里的变量覆写。

运行静态检查：

```bash
sylc check alu_add.syl
```

若设计无误，`sylc check` 将以退出码 `0` 静默退出。

## 第 3 步：使用 `bundle` 与 `select priority` 演进设计

真实电路通常不止一个原始输出。假设我们希望加法器还能根据控制信号 `use_xor: in Bit` 切换为按位异或，并同时输出零标志位 `is_zero: Bit`。

将 `alu_add.syl` 更新为：

```syl
bundle AddResult {
    sum: UInt<8>,
    is_zero: Bit,
}

cell AluAdd8(
    a: in UInt<8>,
    b: in UInt<8>,
    use_xor: in Bit,
) -> rsp: AddResult {
    signal val: UInt<8> :=
        select priority {
            use_xor => a xor b,
            default => a + b,
        }

    rsp := AddResult {
        sum: val,
        is_zero: val eq 0,
    }
}
```

### 硬件语义解析

1. **`bundle AddResult`**：将 8 位的 `sum` 与 1 位的 `is_zero` 打包为一个复合线网类型。在 SystemVerilog 中，它会降级为紧凑的 9 位向量 `[(8 + 1)-1:0]`。
2. **`signal val: UInt<8>`**：声明内部组合逻辑线网。`signal` 没有时钟也没有记忆功能，纯粹代表组合逻辑连线。
3. **`select priority { ... }`**：描述一个带优先级的多路选择器（MUX）。当 `use_xor` 为 `1` 时，`val` 由 `a xor b` 驱动；否则由 `default` 分支的 `a + b` 驱动。强制要求 `default` 分支确保了 `val` 永远不会处于未驱动状态（从根源上杜绝意外锁存器）。
4. **`val eq 0`**：硬件相等比较使用 `eq`（返回 `Bit`）。Syl 将 `==` 与 `>` 保留给编译期常量或命题表达式使用。

再次运行 `sylc check`：

```bash
sylc check alu_add.syl
```

退出码为 `0`，说明设计已通过静态检查。

## 第 4 步：生成并解读 SystemVerilog

现在将 `AluAdd8` 编译为 SystemVerilog：

```bash
sylc emit alu_add.syl
```

输出如下：

```verilog
// Generated by sylc. MVP SystemVerilog subset.

module AluAdd8 (
    input [7:0] a,
    input [7:0] b,
    input use_xor,
    output [(8 + 1)-1:0] rsp
);
  wire [7:0] val;
  assign val = /* priority */ (use_xor ? (a ^ b) : (a + b));
  assign rsp = {val, (val == 0)};
endmodule
```

可以看到 Syl 与可综合 SystemVerilog 之间非常直接的映射关系：
- `signal val: UInt<8>` 映射为 `wire [7:0] val;`。
- `select priority` 映射为三目运算符 `assign` 表达式。
- `AddResult { sum: val, is_zero: val eq 0 }` 映射为位拼接 `{val, (val == 0)}`。

## 第 5 步：体会 `sylc` 的编译期错误拦截

在传统 Verilog 中，对同一根 `wire` 写两条 `assign` 语句往往能通过编译，直到仿真时才暴露出 `X` 态冲突。而在 Syl 中，每根信号**至多只能有一个驱动源**（且每个输出端口**至少必须有一个驱动源**）。

尝试创建 `bad_driver.syl`：

```syl
cell BadDriver(
    a: in UInt<8>,
    b: in UInt<8>,
) -> sum: UInt<8> {
    sum := a
    sum := b
}
```

运行 `sylc check bad_driver.syl`：

```text
error[E_MIDDLE_DUPLICATE_HARDWARE_DRIVER]: duplicate hardware driver for sum
  --> bad_driver.syl:6:5
   |
 6 |     sum := b
   |     ^^^^^^^^
   |
note: previous driver claim
  --> bad_driver.syl:5:5
   |
 5 |     sum := a
   |     ~~~~~~~~
   |
note: conflicting driver claim
  --> bad_driver.syl:6:5
   |
 6 |     sum := b
   |     ~~~~~~~~
   |
error: aborting due to 1 previous errors
```

`sylc` 在编译期直接以 `E_MIDDLE_DUPLICATE_HARDWARE_DRIVER` 拦截了冲突驱动，无需启动仿真器。

## 常见踩坑与排障

- **写成 `in a: UInt<8>` 而非 `a: in UInt<8>`**：Syl 的端口语法将端口名放在冒号前（`端口名: 方向 类型`）。
- **使用保留字作为端口名**：`out`、`in`、`reg`、`signal` 均为关键字。输出端口请使用 `rsp`、`result` 或 `dout` 等名称。
- **在硬件表达式中误用 `>` 或 `==`**：Syl 严格区分软件常量运算符与硬件运算符，在 `signal` 上使用 `>` 会触发 `E_MIDDLE_SOFTWARE_OP_IN_HARDWARE`。硬件相等比较请使用 `eq`。
