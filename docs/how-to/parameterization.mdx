Syl separates compile-time elaboration (`Nat`, `Bool`, `fn`, `const`, `for`, `if`) from runtime hardware (`Bit`, `UInt<W>`, `signal`, `reg`). This lets you write highly reusable, parameterized hardware generators that are statically checked before SystemVerilog emission.

## Generic `cell` and `bundle` Parameters

```syl
cell RegisterFile<W: Nat, DEPTH: Nat, D: Domain>(
    clk: in Clock<D>,
    rst: in Reset<D>,
    we: in Bit,
    waddr: in UInt<clog2(DEPTH)>,
    wdata: in UInt<W>,
    raddr: in UInt<clog2(DEPTH)>,
    rdata: out UInt<W>,
) {
    ...
}
```

## Compile-Time Validation with `check_fn` and `check_map`

Use `compile_error` inside `fn` or `check_fn` / `check_map` to enforce parameter invariants (such as power-of-two depths or minimum widths) at elaboration time:

```syl
fn is_pow2(n: Nat) -> Bool {
    return n > 0 and (n & (n - 1)) == 0
}

check_fn require_pow2(n: Nat) {
    if !is_pow2(n) {
        compile_error("DEPTH must be a power of two")
    }
}
```

Similarly, `check_map` validates constraints on `map` combinational transforms before lowering.

## Structural Generation with `for` and `if`

- **`for i in 0..N`**: Unrolls at elaboration time, generating `N` independent hardware instances or wire connections.
- **`if cond { ... } else { ... }`**: `cond` must be a compile-time `Bool`. Untaken branches generate zero hardware.

```syl
for i in 0..LANES {
    let lane = place LaneCore<W, D>(clk: clk, rst: rst, din: din[i], dout: dout[i])
}
```

## Best Practices

1. **Validate early**: Guard every generic `cell` with `check_fn` or `compile_error` so invalid parameters fail with a clear message instead of downstream width mismatches.
2. **Watch `for` loop area**: `for i in 0..1024` elaborates 1024 physical hardware copies.
