# Syl Documentation

Syl is a statically analyzable hardware description language (HDL) designed to catch hardware bugs—missing drivers, overlapping drivers, width mismatches, CDC violations, and reset-domain mismatches—before SystemVerilog emission.

This documentation is organized according to the **Diátaxis** framework into four distinct quadrants, so you can find the right level of detail whether you are writing your first `cell`, migrating an existing RTL codebase, looking up a grammar rule, or studying the Salsa incremental compiler.

## Production-Grade Syl at a Glance

### Salsa Incremental Engine
Syl's compiler (`sylc`) and language server (`syl_lsp`) share a **Salsa-based incremental query database**. Editing a single `.syl` file only recomputes the affected syntax, HIR/TIR, elaboration, and static-check queries, giving sub-second diagnostics in your editor and fast incremental builds in CI. See [Salsa Incremental Architecture](/docs/explanation/salsa-incremental-architecture).

### `syl.toml` Workspace & Package Manifest
Multi-file projects are configured via `syl.toml`, which defines package names, source roots, target SystemVerilog emission options, and `extern` IP bindings. See [Configure `syl.toml`](/docs/how-to/configure-syl-toml) and [Manifest & Opaque Schema](/docs/reference/manifest-and-opaque-schema).

### Static Hardware Guarantees
Every `sylc check` run verifies:
- **Driver completeness & exclusivity**: No undriven outputs (`E_MIDDLE_MISSING_HARDWARE_DRIVER`) and no multiple drivers (`E_MIDDLE_DUPLICATE_HARDWARE_DRIVER`).
- **Width & type safety**: Exact bit-width matching (`E_MIDDLE_TYPE_MISMATCH`) and `Bool` vs `Bit` separation.
- **Clock & Reset Domain Crossing (CDC/RDC)**: Explicit `Clock<D>` and `Reset<D>` domain tracking (`E_MIDDLE_CDC_VIOLATION`), reset polarity consistency, and synthesizable RAM/FIFO inference.

See the [Diagnostic Index](/docs/explanation/diagnostic-index) and [Diagnostics Reference](/docs/reference/diagnostics).

### 13 `std.*` Standard Library Modules
Syl ships with 13 built-in standard library modules covering arithmetic, bit manipulation, synchronization, FIFOs, memories, arbiters, and bus protocols. See [Standard Library Reference](/docs/reference/standard-library) and [Standard Library Patterns](/docs/how-to/standard-library).

### `syl_lsp` & Editor Support
`syl_lsp` provides real-time diagnostics, hover types/widths, go-to-definition, and workspace symbol search powered by the same Salsa database as `sylc`. See [LSP & Editors](/docs/how-to/lsp-and-editors).
